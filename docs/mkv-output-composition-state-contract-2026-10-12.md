# 软封工作台：输出组成投影的状态契约

状态：**PR #74 工作中，Issue #75 第一实施单元；尚未替换旧 UI，也未经新 head 浏览器验收。**

## 主要工作对象

主界面未来应呈现“当前将写入的 MKV”的轨道与附件，而非把输入分类、ffprobe 诊断、编辑卡和完整封装计划重复排列。

当前已加入 `src/output-composition.js` 的纯函数 `buildOutputComposition()`。输入来自既有可写状态：`videoInput`、已验证且与当前视频相符的 `trackState`、`appendPreserveAll`、`externalAudioState`、`newSubtitleState`、已选字体及不可用输入。它只返回显示对象与稳定目标索引，**不是命令生成器，不直接修改任何轨道属性，不是第二套编辑状态。**

| 状态来源 | 呈现对象 | 允许的编辑入口 |
|---|---|---|
| 尚无 FFprobe 验证的源文件 | 一项“源轨道待核验”占位；不得猜测视频/音频轨数量 | 查看源文件与等待验证 |
| `trackState.streams` | 真实的原视频、音频、字幕、附件；以 `codec_type:index` 保持选中身份 | 复用现有 `assetInspectorHost`，不复制控件 |
| `trackState.tracks / attachments` | 保留、修改、排除和排序后的原轨结果；排除项仍可查看和恢复 | 现有源轨控制及保护模式 |
| `externalAudioState / newSubtitleState` | 新增独立轨道，文件身份稳定，不以列表位置充当 ID | 原新增轨道编辑器 |
| 已选字体 | 新字体附件；与原附件区分；强制字体模式遵守现有 ASS-like 条件 | 原字体配置 |
| 不可用输入 | 隔离的诊断对象，绝不假装为输出轨道 | 原导入资源的诊断/移除动作 |

在完整保留原 MKV 的默认模式下，即使旧内存中残留了选择性改轨字段，投影仍将原轨视为保留状态。切换到选择性编辑时才显示真正的排除/修改。源章节和容器全局元数据是容器级信息，不伪装成独立字幕或音频轨。未扫描前轨道计数不得冒充已验证。

## 下一实施边界

1. 在 `src/main.js` 中，用当前源文件匹配的 `trackState` 驱动唯一的输出组成视图；点击轨道按 `target` 跳转**现有**编辑控件，绝不额外持有 title/default/forced 等属性。
2. 已有源文件时收起大幅拖放空态。将 FFprobe 原始详情、完整计划放入按需查看区域；诊断和错误不得被折叠掉。手机采用组成清单与就地编辑，不要求用户依次跳四个页面。
3. 用真实文件覆盖 MP4 源未扫描、MKV 原轨保护、选择性排除、同名附件、字幕与外部音频、无视频轨、不支持输入及 320/390/1440px 的选中态和导出审计。浏览器截图未检查前不得声称最终布局已达到要求。

**约束：** 源和视频/音频码流只做 Stream Copy；预览成功、兼容性规则命中、mux 成功、ffprobe 成品审计各自代表不同证据。不得以简化 UI 为由吞掉失败原因、隐藏改动或静默启用破坏性编辑。
