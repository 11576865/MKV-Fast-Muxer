# 无视频音频容器封装（0.1045）

在统一“添加文件”入口选择实际包含音频的 MKA、M4A/MP4/MOV 或 WebM。多个容器时，像现有视频工程一样明确选择主来源；不需要视频宿主。MKA 扫描后可在来源树选择、排序和修改原音轨标题、语言、标记，再加入外部音频、字幕和字体，点击现有封装按钮。输出沿用 `.mkv` Matroska、报告及目录保存入口，实际没有视频流时不创建视频轨。

保留全部模式复制来源 stream 集并追加资源；选择模式按参与输出的轨道执行。来源没有视频时，至少保留一条原音频或加入一条参与输出的外部音频；全部排除会明确拒绝，重新勾选后可继续。原音频保持 Stream Copy，不提供音频转码。MKA 音轨与外部资源仍属于同一个现有工程及编辑历史。

来源要经实际 ffprobe 验证和执行边界文件头核对。Matroska 章节、标签和 UID 风险保护继续生效。纯音频路径启用 `-copyts` / `-avoid_negative_ts disabled`；单项时间轴核验不是任意编码器延迟、播放器同步或完整容器保真证明。成品回读音频/字幕清单、ASS 事件和字体附件字节；实际通过范围以报告为准。

## 验证范围

自动场景：`tests/e2e/audio-only-mux-scenario.mjs`。实际浏览器生成五份零视频输出：双音轨 MKA 保留、修改原音频并附加外部音频/ASS/字体、排除原音频后的外部替代、AAC M4A 来源、Opus WebM 来源。系统 FFprobe 核对音频包哈希和数量，保留 MKA 的每包 PTS（1.1 ms 容差）及编码私有数据；独立提取字体比较完整 SHA-256、读取 ASS 文本。空音频输出及纯字幕来源拒绝、调整后恢复、输入文件未改动均需通过。

测试素材为受控短片，非长音频性能、物理平板或播放器验收。原生 FLAC/AAC/MP3 等裸流仍作为外部音频；本轮不把它们升级为主来源。不扩展批量纯音频任务，不支持从纯字幕 MKS 开始通用封装，也不承诺音频来源的视频帧预览。普通非字体附件与完整 EBML 编辑仍遵循现有能力边界。
