# 媒体与普通附件（0.1046）

在统一“添加文件”中导入主媒体、字幕、字体与 PNG/PDF。未识别文件（例如说明、JSON、许可证或其他二进制文件）不会自动获得格式支持；点击该行“作为普通附件”，以 `application/octet-stream` 保存原始字节。它不是音视频轨，也不进入字体或字幕解析器，不会自动打开或执行。

每个普通附件可勾选是否参与输出。普通附件最多8项，非空、单项不超过16MiB，合计不超过32MiB；路径字符、设备保留名称和不安全名称需在外部重命名后重新导入。与保留的原附件、新字体或其他新附件重名时，为新普通附件增加安全序号。原始名称、实际成品名、MIME、字节数与完整SHA-256均写入报告。

点击现有封装按钮即可生成包含媒体、字幕、字体和普通附件的 MKV。纯音频主来源也适用。普通附件单独存在时仍使用现有零媒体轨道的纯附件写入器。批量任务暂不增加普通附件配方。普通附件的选择不属于本轮新增的可撤销领域历史或可携带恢复草稿。

## 成品验证

来源实际容器身份、Matroska保留风险及音视频兼容性仍须通过。普通附件以准确 File 引用、参与状态、MIME绑定，实际送入worker的字节先记录摘要和长度（跨worker传输会分离数组缓冲区），完成后再从最终EBML FileData读取，核验名称、MIME、长度和完整SHA-256。此项未通过则不发布新下载，不把ffprobe数量一致当内容一致。完成后的证据区与报告分别列出原附件、新字体、新普通附件的字节验证。改变选择会让旧成品证据失效。

末段ASS/SubRip成品审计期间取消也必须在最终发布处阻断；下次可重新加载核心重试。生成和核验不代表文件已写入物理磁盘。

## 来源图片附件

FFprobe会把某些Matroska图片AttachedFile投影成`attached_pic`视频流，直接`-map 0`可能将它改写成视频轨。本路径仅对实际Matroska、带附件名称/MIME的图片投影做区分，再独立从来源FileData读取，排除原图片stream映射并重新附加。保留或选择模式下，源图片文件名/MIME的现有编辑都继续适用。

图片回附需唯一绑定实际原文件名/MIME，当前每项16MiB、合计32MiB，超限或结构证据不足会明确拒绝。本轮不承诺图片FileUID、目标标签、全部EBML层级或ISO BMFF封面轨语义保留；其他原附件仍沿用已有写入和字节审计政策。MIME只是声明，验证不证明内容安全或任意播放器兼容。

## 具名验收

`tests/e2e/media-attachments-scenario.mjs`：真实浏览器媒体来源含原PNG/字体，新增PNG/PDF/显式指定的JSON（伪字体扩展名）、ASS和字体。独立回读成品FileData并以系统FFmpeg提取对比完整哈希，核对媒体每包哈希和PTS、共享重名分配、排除/重新加入和旧证据失效。另核验原图片重命名/原字体排除、纯音频加PDF、末段审计取消及重试。原纯附件场景继续生成零轨道成品，并验证旧诊断选择器的媒体不会被忽略。受控短素材不替代长媒体、实体平板或1.0完整验收。
