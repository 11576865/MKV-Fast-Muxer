# 软封：现有功能与通用工作流的连接点审查（2026-11-01）

状态：**研究候选 / 用户行为尚未批准 / 无产品代码变更 / 非正式 1.0 验收**。不能用这份研究替代 2026-10-12 已批准方向与 2026-10-20 范围 B；不得据此删除旧能力。
基准：仓库 `main` README 标记开发版 `0.1032.0`；PR #205 仍为未合并的 0.1033 发布证据提案。具体模块证据来自此次读取的默认分支源代码；未执行生产站点实机验证。

## 1. 用户行为边界（来自 2026-11-01 讨论，非完整实现规范）

- 从拖入文件开始，不先区分“封字幕、打开容器、封附件”。
- 打开 MKV 后自然呈现可检查的内容；用户可继续操作，也可直接退出。**没有独立的“只查看功能/模式”**；只有在明确生成时才输出 Matroska。
- 一个输入 MKV 可以自然打开查看；多个 MKV 可以分别打开，不因导入而自动合并或要求视频拼接；无输入 MKV 也应能构造候选容器（包括附件-only）。
- 导入/观察、当前选中对象、参与拟输出的成员资格、执行及实际保存是不同状态。
- 保留原有一键字幕/字体封装的低操作成本；批量现有能力保留，但新通用功能**无需**同时支持批量，容许个人用户战术性重复手动操作。
- 外部附件和跨来源对象操作仅在实际支持及独立验证后可执行；不可从领域表示能力推导当前 writer 能力。

### 目前用户模型与实际代码的明确差距

1. `resolveImportedRoles` 的一个主源决定执行适配器，这不是多个 MKV 之间的无副作用内容检查器。
2. `buildOutputComposition` 为每条已有 `newSubtitles` 与 `externalAudio` 设置 `included: true`；字体亦随全局模式选择成品附件。当前“被导入和选为外部轨道”与“拟输出成员”仍紧贴，**不支持通用资源库中任意候选字幕只供预览**。
3. `refreshSubtitlePreview` 明确无 `videoInput.files[0]` 时提示“等待视频与 ASS / SSA”，这是原版视频画面静态帧预览的实际能力边界；不是独立字幕预览器。
4. `classifyAssetBytes` 的未知分支返回 `UNSUPPORTED`；普通 PNG/PDF 目前不会自动获得“可作为 Matroska 附件”的角色。
5. `projectMatroskaTarget` 可以描绘无视频附件-only，但无法据此完成实际封装；必须使用经过独立验证的专用写出路径。
6. `index.html` 当前仍有显著分立的外部字幕属性、字体模式、字幕预览、容器属性、输出组成与批次 UI；按钮存在不代表一个用户操作可以跨功能无损衔接。

## 3. 具体取舍：保留什么，重构什么，隐藏什么

| 操作/功能族 | 处置 | 首次需要证明的行为 |
|---|---|---|
| 旧版视频 + ASS + 字体一键封装 | **保留原执行机制，测试后接入新入口** | 操作成本不明显增加，成品媒体轨与附件真实正确 |
| MKV 打开后的自然内容展示 | **复用已有 scanner**，不要命名独立“只查看”能力 | 打开后可观察内容，关闭不生成产物；这属于基本交互预期 |
| 多个 MKV 的打开/切换 | **检验对象焦点与来源绑定**，不创造跨来源 writer | 查看 A/B 的内容不自动合并或启动另一个工作流 |
| 没有 MKV 的候选组成 | **复用 target 投影，单独补实际附件 writer** | PNG/PDF 组成合法无媒体轨道 Matroska，独立提取和 SHA 对照 |
| 未使用 / 错误导入文件 | **延长导入资源的独立生命周期** | 不强制加入输出；移除会话引用不改磁盘，引用中移除给出依赖影响 |
| 多份外部 ASS 预览 | **复用渲染器，重构调用上下文** | 预览 B 不改变 A 的输出成员资格；明确缺视频时现有渲染能力受限 |
| 字体模式、匹配、HarfBuzz 子集 | **复用算法，按字幕 / 目标绑定决策** | 预览和输出使用的字体环境有可解释来源，改变一份 ASS 不污染其他任务 |
| 原批次配对 / Group 子集 / 队列 | **保留现有受限能力，暂不扩大** | 旧批量配方照常运行；新增通用对象操作不必具有批量版本 |
| 旧重复可写列表 / 强制阶段导航 | **仅在替代完成且经测试后退役** | 一个对象没有多份独立修改权威；旧功能无静默消失 |
| 复杂章节标签、任意跨 MKV 轨道迁移 | **只读/能力边界阻断，不作为当前前置目标** | 不误报“安全保留”，已有复杂 EBML 反例在写出前被识别 |

**重要区别**：隐藏无关高级控件不等于删除专业能力；允许手工重复执行多个输出不等于退役已有批处理。旧 `L-001–L-044` 清单仍有约束力，其迁移台账不应被“全部已验收”或“全部未实现”简单概括。

## 4. 三个真正任务 + 一个默认行为回归条件（禁止把默认行为升级为功能）

**J1 原版体验回归**：导入视频 + ASS + TTF → 正确预检和时间点字幕预览 → 选择字体策略 → 输出 MKV → 独立检查轨道/附件及字体；不得因为新的资源库先多做一轮无意义身份设置。

**J2 自然打开/切换的回归条件（不是独立产品功能）**：导入 A.mkv，自然展示其已识别内容；再导入 B.mkv，可切换查看并返回 A。直接关闭不会生成文件。该条件只用于防止意外状态修改、强制输出和来源串扰，不能据此建设一套“只查看模式”。

**J3 从零创建附件容器**：仅 PNG + PDF → 显示未保存、附件型 Matroska 候选组成 → 排除 PDF → 明确输出 → 独立 MKVToolNix 回读并验证 PNG 字节。**实际 writer 尚未在当前主执行路径验收**。

**J4 含候选资源的字幕选择**：导入 A.mkv、A.zh.ass、A.alt.ass、字体 → 查看并分别预览字幕候选（预览条件不满足时明确提示）→ 仅选一份作为拟输出 → 回到主容器 → 检验成品确实只新增所选字幕及其应附带的字体。当前系统外部字幕默认全部 `included`，该选择边界需要新代码/真实验证。

每个任务必须同时检查：来源 File 身份、用户选择、保留/排除状态、预览使用的资源集合、执行引擎能力、成品独立回读结果、保存状态与失败后的恢复。预览可用不是整个任务通过。

## 5. 对交互原型的判断

独立浏览器原型（`softmux-interaction-study-20261101.html`，本会话交付，未合入产品）验证的是打开/切换以及 J3/J4 的**状态切换概念**：资源库、来源查看与拟输出草稿互不隐式包含。Chromium 点击测试经过：两个 MKV 不自动合并、打开 B、建立 B*、选择另一 ASS、显式加入/排除、纯附件草稿、未要求生成时无输出，均无 JS 页面错误。演示 MKV 内部对象是显式的模拟数据，绝非真实 EBML/FFprobe 解析。导入本地文件也只有扩展名候选分类；原型的“生成 MKV”被明确禁用。

原型仍有待检验决策：`单个 MKV + ASS + 字体` 时怎样既不隐式覆盖用户意图，又保持旧版一键封装的低操作成本；直接打开已有 MKV 与新建目标草稿的命名/切换如何呈现；平板触控聚焦与视觉密度。这些不是让 owner 预先做更多抽象选择题的理由，应该由可操作演示和旧版回归实验来决定。

## 6. 可执行的下一工程切片，不引入新的万能模型

1. 在正式产品上固定 J1 为旧版行为回归基线，至少真实 FFmpeg 输出、独立轨道/附件审计、同一 ASS 预览及字体匹配；避免重写渲染器。
2. **优先检查打开 MKV 时的默认展示与来源绑定**：一个/多个 MKV 自然展示内容，绝不为无输出意图另建“只查看任务”或新模式；仅在确实发现查看焦点与写入角色互相影响时，才局部解耦；确保 J1 不退化。
3. 在已有资源清单中增加清晰的“已导入但尚未用于目标”语义；独立 preview focus 不改变现有输出选择，并定义明确加入/排除控制；优先解决 J4 影响字幕与字体的问题。
4. 针对 J3 接入受限且独立验证的附件-only writer。设计可以先于 writer，但**不能**把只读 `projectMatroskaTarget` 的绿灯当成产物。
5. 批处理保留现有独立运行队列，测试 L-032–037，暂时不承担新增通用写入和附件操作的批量化。

所有新设计决定必须通过 J1/J3/J4 的跨功能验证与 J2 的默认行为回归，不能靠界面截图、单测或模型自洽代替真实成品。复杂嵌套 Chapter/Tag 保真仍遵守现有 fail-closed 安全政策。

## 2026-11-01 纠偏：不要把打开后自然呈现内容制造成产品功能

用户以游戏启动后自然展示主菜单为例，指出“打开 MKV 能看内容、可不输出”只是软件正常行为。上一版把它命名为 J2“只查看”，并产生模式、路径及工程分层要求，是助手把非强制行为扩张为独立需求的例子。此文件将 J2 降为默认行为回归条件（可检查无副作用，但不是产品功能）；不再建议为查看创建独立任务/模式/架构。能解析轨道和附件的具体能力继续属于已有对象检查能力，但不等同于一个“只查看模式”。这也是用户对研究流程反复膨胀的明确反例。该纠偏不授权新增任何产品工作。
