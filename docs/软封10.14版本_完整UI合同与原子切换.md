## 0. 版本权威与禁止事项

1. **产品标识**：\`软封0.1014版本\`，UI 呈现用；本合同内残留的“10.14”均为此前历史代号，不再是用户认可的产品版本。**已发布包**仍以 \`package.json.version=1.2.2\` 为当前 manifest 事实；整体验收与发布前不得谎称其已经更新或部署。不得盲目修改其他 producer/consumer 版本、JSON report schema。
2. **UI 合同**：以此文与 10-12/10-13 正式决议共同解释目标，其中已批准的语义优先于细节线框。UI 具体视觉还需要真实截图审阅。
3. **实现身份**：仅 \`feat/softmux-10.14-cohesive-workbench\` 是此次 10.14 UI 的权威实现分支；PR 指向 \`main\`。其他线程不得建立平行 10.14 业务模型、DOM root 或第二个 UI PR。
4. **精确证据**：每次验收记录 \`base SHA\`、\`head SHA\`、测试场景、环境、输出实际文件、结论和未知边界。PR 数/测试数不是完成百分比。
5. **一次产品级切换**：可以在唯一分支中多次提交、修复、审查，但**完整 UI 通过门禁前不能把局部过渡界面并入 main 或当成 10.14 正式版**。
6. **不新增通用功能范围**：不把 Matroska 格式许可冒充后端能力；不引入 ASS 创作器、字体设计器、视频剪辑、万能 EBML 写入器，也不借 UI 重构解决 #151 仍未验收的 +21ms 字幕重试问题。

## 1. 完整信息架构，一次呈现

### 1.1 单工程（默认视图）
- 顶栏：固定版本、单工程/批量任务/容器工具、添加资源、帮助、狭义设置；不能隐藏全局诊断/风险。
- **左侧来源**：内容识别的文件/文件夹、源 MKV 摘要、原轨道/附件、外部音频/字幕/字体来源、重新关联与来源冲突。来源不构成另一个轨道编辑器。
- **中央拟输出 Matroska**：单一拟输出容器真实对象集合（视频、音频、字幕、附件、章节、标签），保留/新增/排除/修改意图，稳定身份，当前能力/风险状态。仅 UI 投影，不为演示创建虚假轨道。
- **右侧对象检查器**：当前选择的对象及其适用属性；字幕按需静态预览、字体依赖、来源引用、验证与专业上下文帮助。不可操作的字段必须解释权限/后端边界。
- **下方执行区**：封装任务与取消、计划风险、成品实际哈希/流/字体/字幕审计、下载 MKV/报告；实际封装、实际验证、实际保存分开声明。
- 空状态不可用模拟文件名/数据冒充真实；重要失败不能只显示绿色勾号。

### 1.2 批量任务
- 按配方形成**多个独立拟输出容器**的任务矩阵；每行有自己的来源、字幕配对、字体规则、冻结计划、检查状态与成品。
- 以真实 \`Batch Recipe v2\` / \`JobPlan\` / \`BatchRunner\` 等已有路径为权威。歧义、输出命名冲突和权限异常必须阻断相关任务且可定位。
- 执行、取消、已完成 Blob、目录保存与回执状态不互相覆盖；目前的保存重试/失败重试仅在独立合并与精确 CI 验收后才能宣传为可用。

### 1.3 专业容器工具、帮助、设置
- 专业工具按检查/提取/受限修改聚合，仅在已有预检和真实能力范围内执行。不能为了布局删除原有功能或将尚未验证的实验写入作为正式输出能力。
- 帮助：来源事实/对象属性/安全提示/实际产物验证共用稳定概念；问号是帮助，未验证使用另一状态。
- 设置：**仅应用级显示偏好**放在全局设置；字体处理、轨道元数据和批次配方依然由各自对象/批次拥有。不能悄悄把 UI 偏好写进 MKV。

## 2. 状态权威与数据安全

- 不得创建第二个轨道/附件/批量计划写入状态；现有 \`ContainerProject\` 与来源/外部资源领域权威优先，尚未迁移的部分使用已存在 legacy adapters。
- 列表重排与响应式切换应保留选中对象和未提交修改；帮助/预览/布局切换不是领域 Undo。
- 在第一版候选实现中，采用 **DOM rehosting**（\`appendChild\` 现有节点，不复制 ID、不重复初始化）保护当前真实用户输入、文件权限、事件处理器与输出生命周期；这是迁移手段，不表示已完成所有领域迁移。
- 输出前保持 \`preservation-preflight\`、实际能力解析与相应独立审计，不因 UI 变美而放宽阻断。
- 原始 MKV 和外部文件不能被 UI 布局操作更改或自动上传。

## 3. 旧功能能力迁移（必须逐项复测）

| 旧能力 | 10.14 归属 | 验证重点 |
|---|---|---|
| 视频/字幕/字体快捷封装 | 单工程＋下方执行区 | 真实 MKV、来源未改、无强制多步 |
| ASS/SSA/SRT/WebVTT/PGS/VobSub 识别 | 左侧来源＋中央容器 | 无静默丢轨与不当格式承诺 |
| libass 静态帧预览、时间定位 | 右侧字幕上下文 | 非连续播放器、编辑草稿保留 |
| 字体识别、依赖、子集/策略 | 右侧对应对象 | 原始字体、未知依赖与审计边界 |
| 原轨道属性、排序、附件 | 中央列表＋右侧检查器 | 单一可写权威、UID/索引不串 |
| 专业受限已有 MKV 写入、结构检查/提取 | 容器工具与上下文入口 | CRC、SeekHead、TagAttachmentUID、源保护门禁 |
| 容器计划/工程草稿/重新关联 | 工程上下文 | File 权限不随 JSON 恢复 |
| 封装、取消、错误、下载、JSON 报告 | 底部交付区 | 未保存成品不谎称已交付 |
| 批量配对、Group 字体、逐任务策略、保存 | 批量任务矩阵 | 每行完整状态，歧义不可静默跳过 |

**严禁因为旧 DOM 看起来不符合新设计就直接删除这些控件及其现有 handler**。应通过真实功能迁移表与浏览器端到端测试逐项完成归属验证后，再移除不必要的旧 DOM 包装。

## 4. 响应式和可访问性

- 宽屏：来源、拟输出、当前对象三域并列；局部滚动，尽量同屏完成一次对象编辑。
- 平板：两个主要区域并列，来源在可访问入口/需要时显式调出；不把三列机械挤压。
- 窄屏：一次聚焦来源/拟输出/对象之一，使用明确的视图切换，所有控件保留同一内存实例。
- 支持键盘 Tab/焦点可见、点击热区、无隐藏的主操作、语义化检查器；触摸/长按不能是唯一帮助入口。
- 不用长滚动代替布局、不要重复独立轨道卡片、不要以无关文本淹没风险。

- **已提交的实现尝试**：\`src/softmux-10.14-workbench.js\`、\`src/softmux-10.14.css\`；\`src/main.js\` 使用 \`?ui=10.14\` **显式审查门禁**。原正式 UI 不受影响。可以查看真实来源、拟输出、编辑器、输出和批量处理的原始节点在新容器中的布局。

## 6. 原子正式切换（Release Gate）

候选版**同时**满足以下条件才允许成为唯一默认主 UI：
1. 一份冻结的完整屏幕/状态/交互检查表；不得在切换当天临时更改既定产品对象。
2. 宽屏 1440×900、平板横/竖屏、390×844、360×780 的**真实运行 Chromium 截图**与人工对照；不得使用静态效果图冒充实现证据。
3. 真实来源导入 → 目标轨道/附件编辑 → 字幕按需预览 → 实际生成 MKV → 独立审计 → 实际下载/保存，至少一个复杂 MKV 的拒绝/保留场景。
4. 真正的批量字幕配对 → 冻结 → 多 MKV 输出 → 报告 → 部分失败/取消与既有成果保护回归。
5. 现有 E2E 脚本从当前生产入口迁移到新 UI 契约，原有有效断言不得通过移除选择器/跳过用例而消失。
6. 无第二套编辑状态、无重复 ID、无不可访问入口；视口变换不重建 File 输入控件。
7. 目标 head 对应 Node + Vite + Chromium + 独立 MKVToolNix/ffprobe + 相关 UI 视觉校验**全部通过**；失败必须有可追溯修复，不能从旧提交借用绿色结果。
8. 发布记录保留原产物版本映射和迁移/回滚方案。任何需求尚未实现时，入口状态与限制清楚；不得把“存在 UI 入口”写成“功能已交付”。

**以上所有门槛通过前：此 PR 维持 Draft，\`main\` 使用原稳定 UI，并继续以 \`package.json\` 的现有版本作为已交付事实。**
