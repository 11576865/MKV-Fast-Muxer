# MKV 工作台：对象驱动交互契约（迭代中）

状态：PR #74 提案；自动化及视觉验收未完成。不是已发布的 UI 规范。

## 核心模型

用户操作的对象依次是：**输入文件 → 源容器内的轨道 / 附加字幕 / 外部音频 / 字体 → 最终 MKV**。导入文件是物理资源，封装轨道是逻辑对象；同一项只能有一个可写状态拥有者。

### 资源索引

资源列表应回答“有什么、能否用、当前选中谁”，而不复制完整编辑器。容器文件下的轨道是可选对象；点击轨道在同一个 inspector 中编辑。新导入的字幕、音频、字体在各自资源行直接提供“编辑”，并将焦点移到对应原有表单控件。无法识别、不支持或有内容身份冲突的文件继续就地显示具体证据，不被简洁布局掩盖。

### 编辑器

一个选中对象对应一个可见属性工作区。源轨道属性继续使用 `trackState`，新增字幕使用 `newSubtitleState`，外部音频使用 `externalAudioState`，字体配置保留原有控件。过滤、响应式切换与焦点跳转均不得在 DOM 中复制第二套输入或重置未保存改动。预览是可选的上下文工具，不作为封装的必经步骤。

### 封装

“开始封装 MKV”始终是有明确名称的主操作；待核验、兼容性警告、运行错误、成品下载、审计失败必须仍可理解。批量任务属于独立模式，不能暗中借用单文件选择态。

## 验收门槛

- 1440–1600px：源索引、当前 inspector、MKV 操作互不遮挡且无横向溢出；中列不再重复整棵轨道树。
- 390px：切换源/编辑/输出/批量保持同一 DOM 状态；从资源行点击编辑直接抵达正确字段，保留焦点与用户更改；封装从顶部输出入口进入。
- 真实混合素材：导入 MP4、ASS、外部音频、字体后，可分别进入对应编辑器，随后生成并审计 MKV。
- MKV 原轨：键盘选择轨道、改名、保存；不同窗口尺寸间选择与修改不丢失。
- 安全：未知输入不得静默忽略；源保护模式不得被绕过；流复制、审计、取消、下载及目录冲突路径不因 UI 重排改变。

## 当前范围与未完成项

本轮只修订资源行到现有编辑器的直接入口以及中央 inspector 的宽度约束。进一步减少双层对象导航、精简输出计划的重复呈现，需要以新浏览器截图和使用行为为证据分步推进，不能因为通过源字符串测试就宣布整体重设计合格。
