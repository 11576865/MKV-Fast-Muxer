# V3 整体重构：结构基线与第一条可验收路径（2026-11-07）

## 为什么必须改变实现方式

用户否定了此前在 `src/softmux-v3.css` 上持续增加视口特化规则的结果。原始实现累积了大量 `!important`、`:has()` 与跨区域 DOM rehost，所覆盖的是真实媒体执行器上方的展示结构；它**可以通过媒体 CI，却未必符合批准的 Figma 整体布局**。后续不再把「局部 CSS 修补 + 全绿 CI」视作设计完成。

**本阶段不是创建另一个输出引擎、编辑器、File input，也不是一张静态设计图片。** 保留现有真实 File、观察扫描、源只读、明确目标授权、单一编辑器、FFmpeg.wasm 输出、状态、取消、下载与审计；要替换的是这些原生对象之上的 **Shell / Workspace / Context / Action** 布局所有权。

## 批准的四个关键外壳：来自 Figma 页面 `27:2` 实际节点的框架位置

| 状态 | 视口 | Chrome / 标签区 | Workspace | Footer / 操作栏 |
|---|---|---|---|---|
| V3-01 · `28:2` 桌面来源 | 1440×900 | y=786，高58 | y=0，高786 | y=844，高56 |
| V3-04 · `32:2` 桌面目标 | 1440×900 | y=0，高58 | y=58，高786 | y=844，高56 |
| V3-05 · `33:2` 竖屏来源 | 820×1180 | y=0，高60 | y=60，高1060 | y=1120，高60 |
| V3-06 · `35:2` 竖屏目标 | 820×1180 | y=0，高60 | y=120，高1060 | y=60，高60 |

这些位置取自**已批准 Figma 节点自身的外层 FRAME bounds**，不是从旧 CSS 猜测。尤其：桌面来源的标签栏与桌面目标不同；820px 目标的操作栏在顶端标签下方。它们应由**明确状态布局容器**控制，不能依赖针对某个子按钮的补丁推导。

真实子层在不同视口中的位置还需要第二阶段对齐。标题、统计、操作、轨道分组和上下文会成为与 `shell` 不同的 component slots。

## 新建的可执行基线

- `src/v3-shell-geometry-contract.mjs`：四种经批准的 shell 几何、真实 DOM 区域选择器以及纯函数 `inspectV3ShellGeometry()`。
- `tests/v3-shell-geometry-contract.test.mjs`：验证四个状态的布局互斥、无重叠/空洞、错误位置可被检测；**不允许自动宣称视觉通过**。
- 真实 `tests/e2e/v3-multitrack-visual.e2e.mjs` 与 `v3-source-ass-preview.e2e.mjs`：在实际媒体、实际 File 和真实工作区中抓取 1440 来源/目标和 820 来源/目标外壳的 `getBoundingClientRect()`；原媒体/字体/写入验收不撤销。
- `scripts/ui-v3-build-comparison.mjs`：把四状态实测差异写入 `shell-geometry-audit.json`，并在既有 `review-index.json` 标出 **`shellGeometryAccepted:false`**。若缺任何一个状态，证据生成失败。现有 10 组静态图片对比仍需人工审查；V3-11 是规则板而非第 11 张 UI 截图。

该基线是**有意义的负面证据**：旧界面如果把设计应位于 y=786 的标签栏放在 y=0，就必须写出 -786px 偏差，而非把“有导航栏”判为相符。偏差记录不等于新布局已实现。

## 第二阶段：结构性替换，而不是覆盖旧 CSS

1. 将 Figma 的四个 Shell 格局实现为单一 `V3Shell` 状态驱动布局组件：`source/target` × `desktop/portrait`。一个 DOM ownership graph；原有节点仍唯一，布局层不拥有 File、字幕、字体或 FFmpeg 状态。
2. 对 1440×900 的来源/目标与 820×1180 的来源/目标使用**固定媒体身份、相同轨道及相同字幕/字体状态**重新截图，先过 Shell、轨道列表、上下文和动作；再派生 1180 和 620，而不是反过来打补丁。
3. 先保持重构位于独立 PR 中，不提前修改线上默认 V3。成功准则是四个 Shell 区域的偏差均低于经审查容差、零交互裁切、原生权限/媒体回归绿色，并且相同素材的整屏设计人工签核。
4. 所有暂时无法匹配 Figma 模拟媒体（包括源文件名、六附件、章节与标签）的部分记录为 **`UNMATCHED_FIXTURE`**。只基于结构测量提出局部几何结论，不伪造像素分数或全部 11 状态合格。

## 不可改变的约束

- 正式网站 `/` 仍指向既有合并版 V3；本基线不影响默认 UI。
- `?ui=workbench` 与 `?ui=legacy` 保留原有回退。
- 来源读取不是写入授权；只有精确 `File` 与明确目标才允许输出。
- Browser E2E 的新几何证据与真实 MKV/ASS/字体测试均需独立通过。单纯的绿色单元测试不是结构重建的完成证据。
- 未合并本 PR 前，不宣传重构 UI 已上线。所有设备/辅助技术与软封 1.0 发布仍由 [#256](https://github.com/11576865/MKV-Fast-Muxer/issues/256) 独立追踪。

**本轮交付门槛：** 四状态结构契约 + 真实 DOM 数据采集 + 可复查的差异 JSON + CI。下一轮才开始替换 Shell 代码，且必须以这里观测到的差异为基础。
