状态：**Draft / 视觉改造拒收后的修正方案**。仅适用 `?ui=v3&nav=full`，不更改默认 V3、写入器或来源 File 权限。
关系：[基础 PR #267](https://github.com/11576865/MKV-Fast-Muxer/pull/267)、[来源结构 PR #268](https://github.com/11576865/MKV-Fast-Muxer/pull/268)、[本 PR #269](https://github.com/11576865/MKV-Fast-Muxer/pull/269)，均保持 Draft。

## 1. 决策更正

八阶段顶部大卡片和三条摘要在上一版新建，但**不产生八个独立工作区**：模块只是点击原生资源/配方抽屉、滚动到原生任务矩阵/检查器/运行面板。浏览器截图显示 1440px 同一任务素材首屏起点比旧版下移约 114px；620px 下两套导航加重复摘要严重占用纵向空间。用户反馈“倒退了吧”。这一版的 E2E 绿灯不能作为视觉验收。

**纠正：撤销 `src/v35-batch-workflow.js` 及其 CSS/挂载、八阶段按钮、三条复制状态。** 回归原 `#sf14Batch` 的资源清单—任务矩阵—对象检查器：
- 本来就存在的两个紧凑披露入口 `[data-sf-batch-controls="sources"|"recipe"]` 只在需要时展开，不额外添加八个 stage。
- `#batchPlan`、`#batchJobInspector`、`#batchRunConsole`、`#batchResults` 是同一批次中的原有唯一节点与操作 owner。
- 真实歧义由 `#batchPlan .batch-review-conflicts` 原生显示，禁用的启动按钮明确灰化。**不以导航摘要复制一次状态**。
- 原先修复过的非本任务来源状态 footer 在 Batch/Tools 视图继续隐藏；恢复完整屏幕首屏高度，不裁剪全局标题栏。

此回滚仅撤掉呈现层。**不删除**真正可运行的任务编辑、批量配对、v2 配方、Group 子集策略、停止/暂停、FFmpeg/Wasm 编码链、成品审计和下载权限路径。

## 2. 保留的真实 E2E

`tests/e2e/v35-batch-deep-workflow.e2e.mjs` 不再测试“八阶段卡片能否被点亮”，而是仅使用原生控件：
1. FFmpeg 生成两份真实视频和两条 SRT。一条精确命名配对 A，一条只有集数，故意对 A、B 产生真实配对歧义。
2. 验证没有人工授权时原生 `#batchStartBtn` 处于 blocked，并直接在矩阵显示 `#batchPlan select[data-batch-tie-index]`。不靠重复状态栏说明。
3. 人工明确将歧义字幕配给 B，随后用唯一原生任务检查器编辑 B 字幕标题和 `zho` 语言。
4. 通过原生“配方与输出设置”披露区导出 JSON v2，确认包含实际编辑。
5. 切换原本的字体子集策略为 Group 再恢复（这是 UI 可用性证明，**不是 ASS Group 字体字节结果验收**）。
6. 只选择 2 项中的 B，实际调用原 BatchRunner 生成 1 个成品 MKV；下载成品、审计报告、运行记录。独立 FFprobe/FFmpeg 检查 SubRip 文本、标题、语言、SHA-256 和四份来源文件不变。
7. 在 1440×900、820×1180、620×900 视口验证原生工作区与全局导航位置：八阶段大卡片与三状态复制必须不存在；标题栏、11 类全局入口仍留在视口内；实际素材/配方/任务/成品原生控件均只存在一份；1440px 任务矩阵的首屏位置必须恢复到可操作区域。原图/JSON 作为 Actions artifact。

**测试正确性说明：** 若任一来源/配对流程失败，必须保留 E2E red，而非跳过生成、审计或输出核验。结构性 UI 检查只能补充真实行为测试。

## 3. 尚未获得的证据及限制

- 必须以 **修正后的准确提交 SHA** 的 V3 Pilot、独立 MKV、完整 Browser E2E 再作判断，不继承上一版绿色记录。
- 820/620 的真实浏览器截图需要视觉复核；全套 CSS 计算关系不能凭 Node/unit 断言证明。
- 55 Figma 设计态与 44 条旧能力尚未完成逐项屏幕签核，**不得从本次批量回归推导已完整实现**。
- 长视频、大于 1GB、物理平板、复杂字幕字体闭包、保存失败后真正恢复等不在此 SRT 示例内。
- 产品设计尚待用户再次审查；本 PR 仍 Draft，不自动合并、不切换生产默认 UI。

## 4. 可复用设计判断

“单一原生对象 owner + 所有按钮都能点击”仍可能因为导航叠床架屋而倒退。验收要同时记录执行正确性、首屏有效工作面积、重复导航、真可见控件、操作路径和同任务前后截图。此为 UIGS Candidate/Observation，不升级 Canonical。
