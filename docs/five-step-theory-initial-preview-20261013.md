## 1. P1：唯一文档迁移的实际初步入口

- `src/container-project.js`：有版本号、语义对象、显式编辑意图、revision、来源、provenance、undo、安全序列化；音频、无媒体轨及附件-only 工程草稿可建立，不依赖视频根。
- `createContainerProjectFromProjection` 从当前真实的 `ContainerDocument` 只读投影生成稳定对象 ID 的解绑草稿；主 UI “导出工程草稿”真实下载 JSON。
- 输出 JSON **不含二进制媒体、不含 File/Directory handles、不授予写入权**；来源必须重新关联。已验证模型的语义操作仅在领域草稿；旧的单任务编辑器尚未全面切换为此文档的唯一可写权威。

**未完成退出门槛**：全面领域驱动编辑器、工程导入/可靠 relink、章节和标签可写、跨视图真正单一权威、持久 Undo。不得宣称 P1 已完成。

## 2. P2：规范与当前后端能力的显式分离

- `src/container-capabilities.js`：分开声明“可建立工程计划”“已支持浏览器重封装入口的条件”“仅极窄 Void 位置可追加附件的专用 writer”“附件-only 实验性”“通用 EBML 保留未经证明”“播放器一致性未经验证”。
- 将能力摘要及可展开原因加在现有真实容器组成旁边，不修改既有 P0 **执行时**的独立 Matroska 原始字节预检。
- 原有 Void-slot writer 的严格限制（符合特定布局且来源 ≤60 MiB、附件总 ≤4 MiB、≤8 项）保持不变；复杂 Chapter/Tag、未知元素未解决时仍拒绝危险重封装。

**未完成退出门槛**：任意 MKV 通用安全 writer、替换/删除全部附件/轨道、未知 EBML 保留、通用非播放容器写入。不能将只读投影或能力摘要称为实际 backend。

## 3. P3-B：批量规则可携带、源文件不可冒名恢复

- `src/batch-recipe.js`：`batch-recipe-v1` 只包含保留原轨、字体子集启用、Group/Job 范围；严格 JSON schema 与 32 KiB 输入上限。
- UI 真正导出/导入规则。导入拒绝异常 schema，不恢复文件/媒体、私有目录权限、原成品、旧手工绑定，不会自动开始队列；任务由当前实际媒体身份与配对规则重新建立。
- 单元测试建立 20 集输出计划并查重：**这是纯计划级 20 项，不是 20 项真实 WASM 封装或性能/内存验收**。
- 继续保留现有真实冻结 JobPlan、BatchRunner 与成果保存状态机。

**未完成退出门槛**：含全配对规则与 task-level 覆盖的 Recipe v2、可靠导入配对草稿/重建任务、重新授权后恢复、十集失败重试、20 集真实压力和目录权限测试。

**未完成退出门槛**：单一可写对象中心架构、测量任务操作距离、真实平板输入/缩放/焦点、撤销语义与多窗口空间质量。

## 2026-10-14 P1 增量：断联草稿的真实对象旧值冲突预览（PR #124）

- `src/container-project-conflict-preview.js` 只读构建修改前后差异：逆向重建草稿中已记录的每个被改字段最早旧值；多次修改同一字段合并为一项，再与当前已扫描来源的对象字段值比较。
- 只有 **当前来源身份一致、实际完整 SHA-256 与草稿摘要相符、当前轨道已经过来源扫描** 时才允许宣布“旧值匹配，可以只读预览”。任意单项不满足均标记为阻断，并列出冲突及原因。
- 同名但不同源、只有头部识别的容器、未验证摘要、外部无来源对象、当前字段发生变化、原对象缺失等均不能错误变成可恢复修改。
- 工作台导入草稿后增加可展开的冲突列表；不对旧单任务编辑器、来源文件、任务计划或真正 MKV 写入器执行任何修改。
- 测试包含同字段多次编辑折叠、目标状态伪造、字节来源证据缺失、对象旧值变更、未扫描、来源身份漂移、外部对象的反例；Chromium 实际导入后检查在哈希匹配但未经轨道扫描时仍维持阻断。
