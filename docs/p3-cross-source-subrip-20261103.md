# P3 — A.mkv 内封 SubRip 直接参与 B.mkv 的浏览器输出

日期：2026-11-03。状态：PR 中，**需要准确提交的完整 Node、构建、真实 Chromium 与原生包/时间轴验收**。不得据此标记 S01–S14 全部通过。

## 使用任务

在原有文件列表一次导入 A.mkv 和 B.mkv，打开 B 作为当前 MKV 输出来源。A 仍作为非当前来源保留在同一个资源列表，不会自动合并。

用户按需点击 A 条目的「查看内封字幕」。软封使用已有 ffmpeg.wasm + ffprobe 路径实际扫描 A 的字幕轨道（不以文件名推断）。目前为 `subrip` 的字幕显示「加入拟输出」操作，ASS/SSA/PGS/VobSub 轨道保持只读和明确不支持状态。

用户点击 SubRip「加入拟输出」后，软件从 A 使用 **`-copyts` + `-map 0:<observed index>` + `-c copy`** 经现有浏览器原轨提取器构造一个操作范围内的 SRT File，随后加入已有的字幕选择、编辑、候选预览、封装及成品审计流程。没有要求用户先下载字幕再重新导入，也没有改动 A 原文件、替换 B 来源、另起资源库或新增独立的写入器。

来源标签里的语言和标题经现有外部轨道状态领域接口传入，用户可以继续修改。再次添加同一 A 的相同原始轨道被拒绝。移除 A 时删除所有由 A 导出的 SRT 输出成员，使旧成品证据失效；用户主动移除 SRT 则不删除 A。

## 适用边界与安全约束

- 本阶段只支持**实际探测为 SubRip（`subrip`）**的原轨。来源的 ASS 字体依赖尚不能通过同一封装过程闭合，故此阶段不允许直接“搬运 ASS 轨”，不把 SubRip 的成功冒充全部字幕支持。
- 源轨与当前 B 的时间基准可能不同。采用原轨 Stream Copy 的绝对时间线以及实际输出原生 FFprobe 数据包 PTS/DTS 比较；用户仍需有正确时间轴的来源，不自动执行字幕同步或时基重映射。
- 读取动作占用共享的 ffmpeg.wasm 操作锁；保留来源 File 精确身份，FFprobe 检测轨道索引和 codec，Stream Copy 结果重新 probe。取消、修改来源或失败时不发布半成品。
- 对操作内生成 SRT 限制为非空且不超过 16 MiB，验证其内容签名为 SubRip；不通过自动编解码“修复”错误的字幕。
- 暂不复制来源 A 的 TrackUID/Tags/章节、默认/强制标志或来源字体附件。这是按内容和时间线复制一条字幕进入 B 的新轨道，并非承诺多源对象完整语义图映射。
- B 的复杂 Matroska 保真预检仍应保留全部既有阻断。现有批处理行为与已有单来源封装不变。
- 生成 SRT `File` 暂为当前浏览器工程内的派生成员，工程导出与跨会话恢复仍需要原来源重新授权；本轮不增加无根据的永久文件权限。

## 独立原生真实样本验收

`tests/e2e/cross-source-subrip-scenario.mjs` 用 FFmpeg 独立创建：
- A.mkv：真实视频＋音频＋英文 SubRip；
- B.mkv：真实视频＋音频，无字幕；
- Chromium 操作：导入两者，打开 B，按需查看 A 原字幕，加入一条 SubRip，执行原有封装，下载实际新 B.mkv。

随后用独立 FFprobe 检查源 A 字幕和 B 中新增字幕的压缩数据包 SHA、逐包 PTS/DTS/时长；按轨道检查原 B 视频／音频数据包和时间戳（允许跨轨道合法交错变化），验证来源 A/B 完整哈希未变，确认源字幕语言/标题正确绑定、重复添加被阻断，移除 A 会撤销派生成员和旧成品状态。

CI 上传实际三个 MKV 和验收 JSON。Node 负例覆盖非 SubRip、文件身份和索引问题、不可信字幕字节、重复来源轨道与清理。
